2. برای تتر، Wallex مرجع «واقعاً مستقل» است (صرافی کریپتو، دفتر سفارش واقعی):

3. پیامد عملی: خطای ۱۰ برابری (ریال/تومان) در آینده بلافاصله توسط cross-check
   با اختلاف +۹۰۰٪ خودش را نشان میدهد → انتشار بلاک میشود.

## تصمیمها بر پایهٔ این ارزیابی

1. **منبع اصلی تغییری نکرد** — jahankhahan رایگان، بدون کلید، پوشش کامل
   داراییها + تتر مستقل؛ جابهجایی به TGJU اصلی هیچ بهبودی نمیداد (همان داده)
   و ریسک/زحمت deploy میافزود.
2. **سکه امامی ارتقا یافت** (`rates.coin` → نماد `emami`): تا پیش از این
   «تأییدنشده» بود؛ تطابق دقیق با TGJU sekee (۰.۰۰۰٪) + چک پایدار
   cross-check در هر گزارش ۶ ساعته → از این پس منتشر میشود (الزام مأموریت).
3. **مثقال عمداً منتشر نمیشود**: خارج از فهرست داراییهای مأموریت است و
   semantics آن با فرمول استاندارد ۴.۶۰۸۳×طلای۲۴ سازگار نیست (نسبت
   mesghal/geram18 ≈ ۴.۳۳). تا تأیید صریح منبع، نمایش داده نمیشود.
4. **میز خرید/فروش دلار (فردایی) پوشش داده نمیشود**: هیچ منبع رایگانِ معتبری
   برای buy/sell میز وجود ندارد (TGJU نرخ واحد میدهد؛ Navasan/Arzhaam پولی؛
   BonBast بدون API عمومی). خطهای خرید/فروش «از نرخ واحد ساخته نمیشوند» —
   محدودیت باقیمانده است تا وقتی مالک هزینهٔ API پولی را تأیید کند.
5. **Navasan و Arzhaam رد شدند** — هر دو درخواست API Key پولی دارند
   (مستنداتشان بررسی شد: navasan.tech/webserviceguide، arzhaam.ir/docs).
   افزودن آن فعالاً یعنی Secret جدید + هزینهٔ تکراری برای همان دادهای که
   رایگان در دسترس است. در صورت نیاز آینده به منبع دومِ مستقلِ پولی،
   `src/providers/provider.ts` ساختار افزودن provider جدید را آماده دارد.

## دسترسی Wallex از egress واقعی Workers (بازبینی مرحلهٔ ۴)

تحلیل ۱۷ اجرای اخیر کانال (زمان واقعی، نسخهٔ فعال): خط تتر فقط در ۳ اجرا
(~۱۸٪) ظاهر شد — Wallex از IPهای دیتاسنتر Cloudflare به‌صورت **ناپایدار**
۴۰۳ میدهد (دیدهشده: 08:05/09:15 UTC 403؛ 09:20/09:25/05:35/06:05 OK).
رفتار fail-closed در تمام موارد درست کار کرد (حذف خط، بدون نرخ کهنه/حدسی).
→ راه‌حل: افزودن مراجع مستقل دیگر (Ramzinex/Nobitex)؛ رفتار Wallex حفظ و
رصد میشود.
